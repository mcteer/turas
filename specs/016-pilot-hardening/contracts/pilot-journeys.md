## Mandatory readiness gates

| Gate | Method and acceptance |
| --- | --- |
| G01 Catalog/evidence | Complete fixed inventories; stale/missing/tampered/duplicate receipts rejected |
| G02 Workspace isolation | Deterministic plus authenticated hosted role/membership/primary/pilot boundaries; old deployments cannot bypass binding |
| G03 Durable storage | Local/Blob adapter contracts and actual hosted maximum-size transfer, cross-instance/restart read and verified deletion |
| G04 Hosted processing | Actual scan/parse/render programs, immutable images, malformed input, timeout/network denial/lease-loss/orphan cleanup |
| G05 Maintenance | All required configured classes scheduled and successful; independent disabled-feature cleanup; failure detected ≤5min |
| G06 Recovery | Full matched restore and post-backup denial/replay cases; observed scheduled cadence and RPO/RTO |
| G07 Lifecycle | Every existing policy class, immediate withholding and bounded restart purge, backup expiry honest |
| G08 Access/security | Full role/customer/workspace/owner, injection, secrets, runtime-grant and malicious-file catalog; zero unresolved exploitable blockers |
| G09 Quality | Current deterministic/native boundary checks plus applicable actual-model/source-fidelity review; historical evidence labeled |
| G10 Load | Fixed 25-session workload and per-class thresholds, natural quotas, zero hidden failures |
| G11 Costs | Admitted infrastructure/model envelopes; complete actual/estimated/unknown ledger, no unexplained in-flight dispatch |
| G12 UI | Four CLI WebKit configurations, keyboard/responsive/serious-critical accessibility checks, actual changed hosted pages/backing requests |
| G13 Regressions | Complete affected predecessor registered catalogs; no selective cases or suppressed flaky failures |
| G14 Build/CI | Docs/typecheck/web/eve and all required current PR checks green before merge |
| G15 Preview | Actual private-storage/executor/schema/grant/role checks on explicit Preview target with synthetic records |
| G16 Production identity | Exact deployed commit/alias, schema ledger/grants, configuration and healthy critical classes after merge |
| G17 Core hosted chain | J002–012 positive journeys including accepted records, actual file artifacts and read/denial checks |
| G18 Partner/learning | J013–014 with assigned partner, normal reviewed demonstrations and publication/rejection boundaries |
| G19 MCP consumer | J015 with actual SDK five-category positive reads/citations and revocation, no fabricated fixture DTOs |
| G20 Operations | Runbooks exercised by a separate operator/reviewer; attributable observations and incident/recovery timings |
| G21 Human feedback | At least one internal participant and one assigned-partner participant provide observed-journey feedback; all blockers corrected/rechecked |
| G22 Final release record | Fresh complete evidence bundle, source/schema/config binding, safe summary and owned-resource cleanup; human approval recorded separately |

All 22 are mandatory for full controlled-pilot readiness. A failed core gate cannot
be excluded merely to obtain a green result. A smaller release may ship corrected
infrastructure while the pilot remains pending; it is not full 016 acceptance.

## Separately admitted capabilities

Actual outbound report mail remains disabled by default and is not required for this
initial pilot scope. It retains 009's separate exact sender, recipient, payload,
revocable policy and real provider delivery/reconciliation gate if later included.
Manual engineering/support handoff records do not send messages. Do not install new
connectors. Broad customer login/federation/onboarding is excluded by clarification.

No-benefit learning evaluation may correctly reject a candidate and pass J014;
it cannot enable publication. Real-user feedback is supplied by actual participants,
not manufactured by a test harness or a review agent. A review agent can independently
assess runbooks/evaluation outputs where authorized, but cannot impersonate a user.
