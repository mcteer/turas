# Customer maturity rubric `customer-maturity-v1`

An assessment records one customer or workload, an observation window, the assessor,
six separate dimension states, supporting evidence, the next capability, and a future
review date. It is a reviewed observation, not an automatic score. Product count,
engagement phase, and an average of dimension states never advance maturity.

| State | Interpretation |
| --- | --- |
| Unknown | Evidence is missing or too weak to describe current practice. Explain what is missing. |
| Emerging | A practice is being tried, but ownership or repetition is limited. |
| Established | The practice is repeatable with named ownership. |
| Measured | Outcomes are measured and used to adjust the practice. |
| Scaled | The practice is applied consistently across relevant teams or workloads. |
| Adaptive | Teams use evidence to evolve the practice as needs change. |

Assess **outcome ownership**, **delivery collaboration**, **experience adoption**,
**operational trust**, **platform organization**, and **innovation/AI** independently.
Each known state cites eligible same-customer evidence for that dimension. Unknown
records the missing-evidence explanation and an action to close the gap.

The optional journey-stage summary follows **Explore → Activate → Accelerate →
Optimize → Scale → Transform**. It is a human-reviewed, evidenced description of
the overall journey, not a formula applied to the dimensions. The assessment
rationale explains why the chosen stage fits the observation window; an omitted
stage means the overall journey is not yet assessed. A later review can update any
dimension independently. Replacing an accepted assessment with an older observation
window requires explicit steward acknowledgment.

Observation dates must not be in the future, and the review date must follow the
observation window. A future review date is valid. A retracted assessment becomes
Unknown for current guidance; older accepted versions remain historical and are
not automatically restored.
